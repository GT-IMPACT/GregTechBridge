## Исправления моста

| Изменение upstream | Адаптация Impact | Критичность |
| --- | --- | --- |
| `GregTechAPI`, `GTUtility`, `GTValues` | Точечная замена ссылок на `GregTech_API`, `GT_Utility`, `GT_Values` в ME Drive, ME Chest и GT EU P2P | Высокая: отсутствующие классы |
| Поле `sWireCutterList` имеет тип `GTHashSet` | В дескрипторе поля и ссылках используется `GT_HashSet` Impact | Высокая: одного переименования владельца поля недостаточно |
| `ItemIntegratedCircuit` в подсказках шаблонов | `GT_IntegratedCircuit_Item` | Высокая: проверка `instanceof` вызывается при отображении шаблона |
| `SoundResource` и double-координаты для перегрузки GT EU P2P | Строка из `GregTech_API.sSoundList[209]`; helper преобразует координаты, полученные из целочисленной позиции блока, в int для `GT_Utility.sendSoundToPlayers` | Высокая: отсутствуют enum и перегрузка с double-координатами |
| `IEnergyConnected.injectEnergyUnits(ForgeDirection,long,long)` | Прямой вызов byte-перегрузки Impact через helper; сторона, напряжение, ампераж и возвращённое количество сохраняются | Средняя: upstream ловил ошибку связывания и использовал reflection; адаптер устраняет её на каждом вызове |
| Снятие окраски через `ColoredBlockContainer` | Late-миксин `GregTechIntegrationMixin` и Kotlin-обработчик для GT, AE2 и окрашенного стекла/глины | Высокая: класс отсутствует в Impact |
| `IGregTechTileEntity.canAccessData()` при вычислении состояния машины для Storage Bus | `getGTMachineHash` использует доступные в Impact `isDead()`, `getMetaTileEntity()` и обратную ссылку `getBaseMetaTileEntity()`; сохраняет значения 1/2 | Высокая: `NoSuchMethodError` при подключении ME Storage Bus к Quantum Chest |
| Визуализатор обращается к `MTEHatchCraftingInputME` и `MTEHatchCraftingInputSlave` | Удалена только ветка отображения GTNH proxy-hatches, которых нет в Impact; граф ME-сети сохраняется | Высокая: отсутствующие типы в байткоде |
| Смена Maven artifactId AE2 | Старый `appliedenergistics2` исключён из зависимости Impact, новый мод подключён явно | Критическая: иначе на classpath присутствуют два AE2 |

`Ae2ImpactTransformer` обрабатывает только пять перечисленных классов AE2. Проверка наличия старого API и отсутствия нового использует ресурсы classloader без ранней инициализации GregTech. Late-миксин также ограничен старым API, требует `appliedenergistics2` и `gregtech`, работает на обеих сторонах. Глобальные классы-подмены в пакете `gregtech` не добавляются.

Энергетические byte-перегрузки AE2 остаются совместимыми с `IEnergyConnected` Impact. Современные `IMEInventory` и `IExternalStorageHandler` сохраняют default-мосты к старым методам; отдельный патч Digital Chest по результатам проверки API не нужен. Это не заменяет проверку ввода/вывода сундука в мире.

## Проверки

- `gradlew test build`: успешно, три регрессионных теста. Проверяются реальные классы целевого AE2, корректность стека/переходов ASM, сохранение отправки графа и повторное применение трансформера.
- Краш `run/crash-reports/crash-2026-10-11_02.27.00-server.txt` выявил вызов отсутствующего `IGregTechTileEntity.canAccessData()` из `GT.getGTMachineHash`, после подключения ME Storage Bus к LuV Quantum Chest. Добавлен отдельный регрессионный тест переходов hash 1/2 для отсутствующей, отсоединённой, готовой и мёртвой машины. Всего в проекте семь успешных тестов; повторное подключение сундука в мире после исправления пока не проверено.
- [Аудит кода и бинарных контрактов](ae2-code-audit.md): 8 293 проверок ссылок и интерфейсных callbacks в обе стороны по опубликованным JAR; отдельно проверены reflection и прямое преобразование стороны при передаче EU. Это проверка кода, не запуск Minecraft.
- Клиент прошёл `FMLPostInitializationEvent` и `FMLLoadCompleteEvent`; лог подтверждает применение всех пяти ASM-патчей и миксина окраски. В dev-сборке есть сообщения о недостающих текстурах; они не являются подтверждением функционального теста.
- Сценарии в мире (GT EU P2P, снятие окраски, схемы с интегральными схемами, Digital Chest) отдельно не проверялись. Dedicated server не запущен: Gradle запросил принятие EULA.
